# Explicit `.xctestplan` file, not Xcode's autocreated test plan

The `SubTimer` scheme's `TestAction` references the checked-in `SubTimer.xctestplan` directly instead of relying on Xcode's default "autocreated" test plan (`shouldAutocreateTestPlan="YES"`).

Autocreated plans are managed **in-memory** and regenerated by Xcode every time the scheme is opened or edited in the UI — any test target added by hand via **Edit Scheme… ▸ Test**, or by editing `<Testables>` directly in the `.xcscheme` XML, gets silently dropped the next time Xcode touches the file. A real, version-controlled `.xctestplan` survives that.

See `README.md` ("Troubleshooting") for the exact failure symptom (`Scheme SubTimer is not currently configured for the test action.`) and how to re-point the scheme if this regresses — it's the kind of thing Xcode's UI can quietly undo.
